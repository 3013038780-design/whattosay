# 技术方案与实现难点

研究日期：2026-10-16。以下为方案，尚未实现。

## 常见实现方式

| 方式 | 适用情况 | 本项目取舍 |
| --- | --- | --- |
| 微信原生：WXML / WXSS / JavaScript 或 TypeScript | 主要面向微信，直接使用平台能力 | 当前推荐，页面不多，无需额外跨端编译层 |
| uni-app：Vue 体系编译到小程序、Web 等 | 团队熟悉 Vue，明确需要多端 | 可选；跨端仍需要分别测试平台差异 |
| Taro：React / Vue 等开发多端应用 | 团队熟悉 React 或已有多端项目 | 可选；若以后明确需要网页演示，可重新评估 |

云开发与以上前端框架属于不同层次，可组合使用，不是互斥选项。低代码工具适合快速验证简单页面，复杂的内容规则、离线兜底与持续维护仍需评估工具限制。

## 推荐的分阶段架构

### 第一阶段：本地即可完成救急

小程序界面 → 场景参数 → 本地内容筛选与排序 → 合格候选随机抽取 → 大字展示 / 收藏。

- 本地携带一批已审核原创短句，启动不等待网络请求。
- 场景、对象、熟悉程度是硬条件；日期、季节和节气是偏好条件。
- 先排除不适用内容，再打分、去重和随机，不能在全部语料里盲抽。
- 候选不足时依次放宽时令、风格偏好，保持关系和场景边界；最终使用通用兜底句。
- 本地收藏与本场历史按内容 ID 存储。换设备不会自动同步。
- 整个小程序首次进入仍需由微信加载代码包；本地兜底保证的是核心出句不依赖额外后端请求，不能承诺第一次启动完全离线。

### 第二阶段：内容更新

微信·云开发的云函数 + 云数据库提供版本化的审核内容。小程序先用本地数据，后台获取更新，校验后替换缓存；失败保留旧版本。内容数量增长后按场景分包或增量拉取，避免把所有语料塞进主包。

首版无需自建服务器。云开发的具体开通条件、配额和价格在开通时核对，不默认永久免费。客户端只能读取已发布内容；内容写入和发布权限放在服务端。

### 第三阶段：可选 AI 改写

用户主动输入真实事项 → 云函数鉴权 / 限流 → 合格短句与结构化要求 → 模型改写 → 长度与事实检查 → 展示。

- 救急结果先出现，AI 生成不阻塞初始内容。
- 模型 API 密钥只放服务端环境配置。
- 限制字数、请求频率、超时、输入长度与预算；失败回到审核句库。
- 不把整本书或整场对话发送给模型，只传本次需要的信息。
- 只能使用用户提供的称呼和事实，不能编造领导指导、项目成功、相识年数等。
- 英文强调自然可说，诗歌区分原文引用与原创；出处不可靠则不显示作者归属。
- 模型供应商、调用地区、费用和面向公众服务的接入要求在接入前单独核实。

## 主要难点

| 难点 | 为什么重要 | 实现办法 |
| --- | --- | --- |
| 语料适配 | 同一句话在领导局和朋友局效果不同 | 结构化标签、适用/不适用规则、人工审核与场景样本验证 |
| 出句速度 | 用户被叫起来时无法等长时间生成 | 本地首句、后台更新、AI 可选、失败兜底 |
| 内容自然程度 | 长篇致辞和套话容易增加尴尬 | 短句优先、朗读审核、真实事项可选、不同长度版本 |
| 随机且不重复 | 小语料池很快重复 | 候选池内抽样、本场已用 ID、耗尽后明确重置 |
| 日期和节气 | 节气公历日期随年份变化，时区影响边界 | Asia/Shanghai 规则、可靠日历库或经核验的年度表，边界测试 |
| PDF 资料处理 | 部分是扫描件，提取结果可能有 OCR 错字 | 提取与 OCR 分开、逐条核对、资料留在本地，原创内容单独维护 |
| 微信预览与发布 | GitHub 提交不等于微信上线 | 开发者工具导入、AppID、真机体验、后台提交审核与发布 |

## 第一版验收目标

- 无后端连接时仍能获得通用、指定场景和英文短句。
- 预置内容加载后，点击换句到渲染完成目标不超过 300ms；该数字是产品目标，需在真机验证，尚未测得。
- 场景边界、候选为空、候选池耗尽、收藏恢复有明确行为。
- 日期测试覆盖月底、闰年、跨年、节气交界及年度表有效期。
- 屏幕较小、字体放大、长英文与大字模式下能完整阅读。
- AI 启用后再验证服务端密钥隔离、请求限流、超时、输出校验与兜底。
